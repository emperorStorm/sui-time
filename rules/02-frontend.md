# 前端开发规则

## Vue 与状态

- 使用 Vue 3 Composition API、`<script setup lang="ts">` 和现有 TypeScript 风格。
- 页面局部状态使用 `ref`、`reactive`、`computed`；只有真正跨页面共享时才评估新增状态层。
- 派生列表、日期分组和展示文案使用计算结果，避免在模板或循环中重复解析 JSON 和日期。
- 定时器、窗口事件、文档事件和通知调度器必须在退出登录或 `onBeforeUnmount` 时释放。

## 数据请求

- 页面只能通过 `src/api/native.ts` 调用 Tauri command 或系统插件，不直接访问 SQLite。
- 浏览器演示降级必须与真实返回类型一致，并明确哪些能力只在 Tauri 运行时可用。
- 异步操作要有提交中、失败和重试边界；失败时恢复按钮状态并保留用户输入。
- 不吞掉用户主动操作的错误。自动检查等非关键后台行为可以静默失败，但必须保留手动入口。

## 组件与样式

- 优先使用 `lucide-vue-next` 已有图标，不手写重复 SVG。
- 样式延续 `src/styles/app.css` 的设计变量、尺寸和命名，不引入第二套 UI 框架。
- 固定格式控件使用稳定尺寸、网格或宽高约束，避免标签、计数和加载态推动布局跳动。
- 不在卡片中继续嵌套装饰卡片；桌面工具优先信息密度、扫描和重复操作效率。
- HTML 字符串必须经过 DOMPurify 等已有安全处理后才能渲染。

## 可维护性

- 代码命名、缩进、括号和注释保持当前目录一致。
- 非复用逻辑不单独抽方法；复用前先确认至少存在两个真实调用方或明显复杂边界。
- 单个函数不超过 200 行，关键业务分支用简短中文注释说明原因，不解释显而易见语句。

# 事项与时间规划基线

## 目标与范围

当前用户可以新增、编辑、删除、完成、标记失败和重新打开事项，并在全部、周、月视图中规划日期。支持全天、时间点、时间段、四象限优先级、备注、失败理由、分类和子事项。

## 业务规则

- 标题去除首尾空白后为 1 至 120 个字符；日期和时间分别使用 `YYYY-MM-DD`、`HH:mm`。
- `scheduleKind` 只能为 `all_day`、`point`、`range`；时间段必须同时有起止时间且结束晚于开始。
- 优先级只能使用 `Priority` 类型定义的四个值。
- 事项状态为 `todo`、`done` 或 `failed`；失败理由选填、最多 1000 字，只有失败状态保留理由。
- 列表可按搜索词、日期范围和终态显示偏好筛选；查询结果按有日期、日期、时间、创建时间排序。
- 是否显示已完成和已失败事项读取当前账号的全局偏好，并在全部、周、月三个视图统一生效。
- 周、月视图按日期稳定地将已完成和已失败事项排在待完成事项之后，两组内部保持原有顺序；月视图前四项和溢出浮层使用同一排序结果。
- 周、月视图的待完成事项使用分类原色，完成和失败事项使用同色浅化背景；完成显示对号、失败显示叉号，均不使用删除线。
- 拖动普通事项只更新 `planned_date`；拖到分类只更新分类。
- 删除父事项通过外键级联删除子事项；子事项不独立出现在日期规划视图。
- 父事项完成代表整个事项结束：有 0 或 1 个子事项时直接完成父子事项；有 2 个及以上子事项时先确认，再在同一事务中以统一完成时间完成父事项和全部子事项。恢复父事项时在同一事务中将全部直属子事项恢复为待完成。
- 子事项的新增、标题、完成状态和删除随父事项弹窗“保存”通过同一事务写入；取消弹窗不修改已保存的子事项。
- 完成、失败和恢复操作只作用于已保存数据，不自动保存弹窗中的标题、属性、失败理由或子事项草稿；重复事项单次实例继续使用 occurrence override。
- 点击失败立即写入状态并展开理由输入；取消弹窗不撤销失败状态。点击失败图标恢复待完成时清空失败理由，父事项失败不改变子事项；子事项不支持失败状态。
- 保存和完成事项成功后不显示右下角成功提示；恢复、删除及失败反馈继续保留。
- 所有读写使用当前会话用户作为 `owner_id`，不接受前端传入所有者。
- 月视图每个日期直接显示前四项；更多事项以 `N+` 入口呈现，打开后在固定定位浮层中展示当天全部事项。
- 月视图浮层保留事项顺序、分类颜色、完成状态和计划时间，点击事项复用编辑弹窗；点击外部、按 `Escape`、滚动、调整窗口、切换视图或月份时关闭。

## 数据与接口

- 表：`tasks`，状态和失败理由落在 `status`、`failure_reason`，其他核心字段对应 `Task`/`TaskInput`。
- command：`list_user_tasks`、`save_user_task`、`remove_user_task`、`list_user_task_children`、`sync_user_task_children`、`set_user_task_status`、`count_unfinished_user_task_children`、`complete_user_task_with_children`、`reschedule_user_task`。
- 浏览器模式使用 `api/native.ts` 内存演示数据，不代表 SQLite 已写入。

## 验收与证据

- 覆盖标题、日期时间、时间段、优先级、分类所有权、三态切换、失败理由、父子事务级联、删除和用户隔离。
- 月视图需验收四项内不出现入口、五项显示 `1+`、完整浮层、边界避让、内部滚动、键盘关闭及事项点击。
- 前端：`desktop-client/src/App.vue`、`src/types.ts`、`api/native.ts`。
- 原生：`tauri-desktop/src-tauri/src/lib.rs`、`db.rs`、`models.rs`。

# 待办弹窗完成与浮层交互完善

## 目标

收紧待办编辑弹窗布局，修复完成圆圈底色和属性浮层叠加问题，并让父待办完成时可靠地同步完成其未完成子待办。

## 范围

- 本期包含：待办弹窗宽度与完成圆圈样式、紧急程度和分类浮层互斥及点击外部关闭、父子待办级联完成确认。
- 本期包含：浏览器演示层、Tauri command、Rust 数据访问和 SQLite 事务的一致行为。
- 本期不包含：数据库字段或迁移、子待办层级扩展、重复实例的系列级子待办、完成操作自动保存编辑草稿。

## 用户流程

1. 用户打开已保存待办，未完成圆圈显示白色底色。
2. 用户打开紧急程度或分类浮层时，另一个浮层自动关闭；点击当前浮层及触发按钮外的弹窗区域时，浮层关闭。
3. 用户点击未完成父待办圆圈，系统查询真实未完成子待办数量。
4. 没有未完成子待办时直接完成父待办；存在未完成子待办时显示应用内确认框。
5. 用户确认后，父待办和全部未完成直属子待办在同一事务中完成；取消时不修改状态。
6. 用户恢复已完成父待办时仅恢复父待办，子待办保持原状态。

## 业务规则

- 子待办数量必须从当前用户的数据库数据计算，不受页面搜索、日期范围或完成状态筛选影响。
- 级联完成只处理直属子待办；当前数据模型不支持更深层级。
- 父子待办使用同一个完成时间；已经完成的子待办不重复更新完成时间。
- 完成状态按钮只处理已保存数据，不保存标题、属性或子待办草稿。
- 重复事项单次实例继续写入 `occurrence_overrides`，不修改系列级子待办。
- 完成操作必须校验父待办和子待办的 `owner_id`，不得影响其他用户或无关事项。

## 接口契约

- 前端 API：`countUnfinishedTaskChildren(taskId): Promise<number>`，返回当前用户指定父待办的未完成直属子待办数量。
- 前端 API：`completeTaskWithChildren(taskId): Promise<Task>`，原子完成父待办及其全部未完成直属子待办并返回父待办。
- Tauri command：`count_unfinished_user_task_children`、`complete_user_task_with_children`。
- 原有 `toggle_user_task` 保持不变，用于无子待办直接完成和恢复父待办。

## 数据结构

无 TypeScript 公共模型、SQLite 表字段或 schema 版本变化；继续使用 `tasks.status`、`completed_at`、`updated_at` 和 `parent_task_id`。

## 异常与边界

- 父待办不存在或不属于当前用户时返回明确错误，不返回误导性的零数量。
- 确认期间禁止重复提交；失败时关闭提交状态、保留弹窗并显示错误提示。
- 已完成子待办的 `completed_at` 不得被级联操作覆盖。
- 完成确认框关闭、取消或点击遮罩时不得修改任何待办状态。
- 620px 弹窗在最小桌面窗口中不得越界，长标题、分类浮层和底部操作区保持可用。
